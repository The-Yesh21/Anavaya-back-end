# Courtroom (Multi-Role Trial) Feature — Build Plan

## What you're getting
A real-time, multi-party **courtroom** that feels like a live trial:
- **Live audio** between Judge, Defence, Prosecution & Witness(es) via WebRTC (peer-to-peer mesh — no SFU needed).
- **Invite links** — host creates a trial, copies a link, others open it to join.
- **Structured trial flow** — phases (Opening → Examination → Cross-Examination → Closing), objections, rulings, witness statements.
- **Live transcript** — every statement/action is timestamped and streamed to all participants in real time.
- **Persistence** — every room + full transcript saved to `case_priority_system/courtrooms/{room_id}.json`; reopenable later; one-click export to Markdown.
- **New 4th "Courtroom" tab** in the dashboard = the **lobby** (create/open/reopen trials, copy invite links). The trial itself runs on a focused **`/court/{room_id}` page** opened from the lobby or directly via an invite link.

## How "live audio + transcript" work together (important design choice)
WebRTC carries the **voice** (the real-trial atmosphere). The **transcript** is built from **typed statements + structured courtroom actions** ("Objection — leading question", "Ruling: Sustained"). This avoids flaky browser speech-to-text and guarantees an accurate, exportable record every time. The UI makes this distinction explicit to participants.

## Architecture

### Network topology — WebRTC full-mesh P2P
Each participant holds direct audio connections to every other participant (≤5 peers each for a typical trial). Uses Google's public STUN server for NAT traversal (works on LAN + most internet). **Newcomer always initiates offers** to existing peers to avoid "glare" (offer-collision); existing peers only answer.

### Signaling — WebSocket at `/ws/court/{room_id}`
Greenfield (no existing real-time code). Protocol:
- **Client→Server**: `join`, `sdp_offer`, `sdp_answer`, `ice_candidate`, `statement`, `action`, `set_phase`, `leave`
- **Server→Client**: `room_state`, `participant_joined`, `participant_left`, `sdp_offer`, `sdp_answer`, `ice_candidate`, `transcript_entry`, `transcript_sync`, `phase_changed`

### Persistence
`case_priority_system/courtrooms/{room_id}.json` — holds room metadata, roster, and the full transcript array. Auto-saved on every statement/action and on participant join/leave. A "Finalize & Export" action writes a timestamped `.md` transcript too.

## Roles & permissions
| Role | Audio | In transcript | Special actions |
|---|---|---|---|
| **Judge** | ✓ | ✓ | set phase, sustain/overrule objections, end session |
| **Defence** | ✓ | ✓ | object, examine witness |
| **Prosecution** | ✓ | ✓ | object, examine witness |
| **Witness** | ✓ | ✓ (when examined) | respond to questions |

Judge / Defence / Prosecution are unique (duplicate-role join is rejected with a friendly prompt to re-pick). Multiple Witnesses allowed (Witness 1, Witness 2…).

## Explicitly out of scope (flagged, not built)
- **Server-side speech-to-text** — transcript = typed statements + structured actions (rationale above). The UI states this clearly.
- **TURN server** — STUN (Google public) works for LAN/internet demos; I'll leave a one-line comment where TURN config would slot in.
- **Video** — audio-only per your choice; the WebRTC track code is structured so video could be added later by flipping a flag.
- **Auth/access control on invite links** — anyone with the link can join (acceptable for a demo; noted in the lobby UI).

## Risks I'll handle
- **`localhost` WebRTC** — works peer-to-peer without STUN for same-machine tabs; I'll still configure STUN so different machines on the same LAN connect.
- **Mic-permission denial** — graceful: audio becomes optional, the transcript/UI still fully work, and the user sees a clear "Allow microphone" prompt.
- **Participant disconnection** — peer connections closed, roster updated, room re-persisted, others notified.
- **Duplicate roles** — rejected cleanly with a re-pick prompt.
- **Route shadowing** — `/court/{id}` registered before the static mount (verified during exploration).
