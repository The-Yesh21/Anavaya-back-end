# Project Context — Anavaya Case Priority System

> This document is the human-readable source of truth for the project's objective and the
> local LLM's role within it. The enriched `SYSTEM_PROMPT` in `scripts/langchain_summarizer.py`
> is derived from this file. Edit this document, then mirror changes in the prompt.

## 1. What Anavaya is

**Anavaya** is an AI-powered **case priority / triage system for judicial authorities**. It reads
legal case documents (FIRs, complaints, court pleadings, judgments) and classifies each case into
**High / Medium / Low priority** so that overburdened courts can hear the most urgent matters first.

The system outputs, for every case:
- A **plain-language summary** a non-lawyer can understand
- A **priority classification** (High / Medium / Low)
- A **constitutional justification** (which articles of the Constitution of India are engaged, and why)
- A **decision report** with a Mermaid/DOT flowchart showing *why* the model reached its verdict

The priority decision must be **deterministic and explainable** — a judge must be able to audit
*why* a case was flagged High priority. This is a hard requirement, not a preference.

## 2. Architecture — hybrid LLM + Decision Tree

The system deliberately separates *understanding the document* from *deciding priority*:

```
PDF text ──► [LLM: Ollama, qwen2.5:3b, NVIDIA GPU] ──► structured features + plain summary
                                                          │
                                                          ▼
                              [Decision Tree (CART)] ──► High / Medium / Low priority
                                                          │
                                                          ▼
                              [Rule-based constitutional analysis] ──► justification
```

**The LLM's job is extraction and summarization ONLY. It never decides priority.**

A traditional Decision Tree model (scikit-learn, CART) — trained on synthetic + real cases —
makes the final priority call. This separation exists so that:
- Priority decisions are **reproducible** (same features → same priority, every time)
- Decisions are **explainable** (the tree's split path is rendered as a flowchart)
- The LLM cannot introduce arbitrary or inconsistent bias into the triage outcome

The constitutional justification is **rule-based and deterministic** too — it maps the extracted
features + predicted priority to articles of the Constitution of India. It is *not* generated by
the LLM.

## 3. The LLM's exact role

The LLM (you, when running) receives the raw text of a legal document and must return **one JSON
object** containing exactly these fields:

| Field | Type | Allowed values |
|---|---|---|
| `main_parties` | string | Comma-separated names of all parties involved |
| `case_category` | enum | One of 8 legal domains (see §4) |
| `crime_type` | enum | `Violent` / `Financial` / `Property` / `Non-Violent` |
| `severity` | enum | `Fatal` / `Major` / `Minor` / `No Injury` |
| `vulnerability` | enum | `High` / `Medium` / `Low` |
| `influence` | enum | `High` / `Low` |
| `plain_summary` | string | 3–4 sentence plain-language summary |

These six categorical features, plus TF-IDF features built from the plain summary, are the **only**
inputs the downstream Decision Tree sees. **The quality of your extraction directly determines the
quality of the priority decision.** Mislabeling `severity` or `crime_type` propagates into a wrong
priority for a real court case.

**Classification reasoning:** the `plain_summary` must end with one sentence explaining *why* the
case was placed in its `case_category` — citing the concrete facts (e.g., "the document mentions
seizure of imported goods and a bill of entry, so this is a Customs/Import-Export matter"). The
classification itself is always re-verified by the deterministic rule-based classifier downstream,
so the reasoning makes the choice defensible without the LLM ever deciding priority.

## 4. The 8 legal categories (`case_category`)

| Category | Use for |
|---|---|
| **Excise/Tax** | Excise duty, GST, income tax, sales tax, customs duty, cess, refund, assessment |
| **Customs/Import-Export** | DRI, customs seizure, import/export licence, smuggling, bill of entry, FEMA |
| **Company/Winding Up** | Companies Act, NCLT, oppression, mismanagement, winding up, liquidation |
| **Insolvency/Debt** | IBC, bankruptcy, DRT, SARFAESI, NPA, debt recovery, creditor petition |
| **Constitutional/Writ** | Article 226/227/32, writ petition, fundamental rights, habeas corpus, PIL |
| **Property/Land** | Eviction, tenancy, land acquisition, ownership, title, possession, mortgage |
| **Criminal/Violent** | Murder, rape, assault, kidnapping, dacoity, domestic violence, IPC offenses |
| **General Civil** | Contracts, consumer complaints, arbitration, family law, succession, civil suits |

Each `case_category` maps downstream to one of 4 broad `crime_type` buckets the model was trained on.

## 5. How each feature feeds the priority decision

- **`crime_type` + `severity`** are the strongest signals. Violent + Fatal/Major → High. The tree
  splits on these first.
- **`vulnerability` (High)** raises priority — minors, elderly, disabled, indigent, SC/ST, women in
  domestic-violence cases, and workers/tenants receive constitutional protection (Arts. 14, 15, 39).
- **`influence` (High)** against a vulnerable victim raises priority — it signals a power imbalance
  the State must correct (Art. 14, Doctrine of Parens Patriae).
- **`plain_summary`** is TF-IDF-vectorized and feeds the tree alongside the categorical features —
  so a clear, specific summary (naming the act, harm, and parties) improves classification.

## 6. Constitutional grounding

Feature extraction is grounded in the **Constitution of India**. The mapping the LLM should keep in
mind when reading a document:

- **Article 21** (life & liberty) — engaged in *all* violent/criminal cases, and any fatal/major injury
- **Article 14** (equality) — power imbalance, discrimination, procedural unfairness
- **Article 19(1)(g)** (profession/trade) — commercial, tax, licensing disputes
- **Articles 23 & 24** — trafficking, forced/child labour, exploitation
- **Article 32 / 226** — constitutional remedies, writ jurisdiction
- **Article 265** — "no tax without authority of law" — all tax/excise/customs cases
- **Article 300A** — property rights — land, insolvency, winding-up cases

## 7. Output contract (critical)

Return **only valid JSON** matching the schema. No prose before or after the JSON. No markdown
fences. The downstream parser extracts the first `{...}` block; anything else is discarded or breaks
the pipeline. If a field is genuinely undeterminable, pick the closest category — never invent a new
label, and never leave a field empty.
